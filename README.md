# Kuma converter

Kumaのソースを、読めるGNU C++23のソースへ変換するための独立版です。

この変換器とREADMEは、生成AI（OpenAI Codex等）を使用して作成・編集しています。生成結果の正しさや競技規約への適合を保証するものではありません。変換器は決められた構文規則で動作し、AIや外部APIを呼び出しません。提出、自動ログイン、問題取得、採点待ち、エディタ連携は含みません。

## 内容

`convert.py`が入口で、`kuma/`には構文解析・C++出力とその補助モジュールがあります。単一ファイルへ圧縮せず、変換処理を読める形で残しています。Pythonの標準ライブラリだけを使います。

元の開発用リポジトリやGit履歴、コンテストの解答、認証情報、端末設定は含めていません。生成C++のコンパイルに必要なヘッダは別途用意します。

## 変換する

Python 3.10以降が必要です。次の内容を`example.kuma`として保存します。

```text
n := input
print n + 1
```

このフォルダで実行します。

```sh
python3 convert.py example.kuma -o example.cpp
```

出力先が既にある場合は上書きせず終了します。別の出力名を指定してください。変換時に入力プログラムを実行することはありません。

既定の`--mode mixed`はKuma変換を明示します。C++として書いた部分とKuma構文を併用できますが、任意のC++が無変換で保持されるモードではありません。

`--mode cpp`は無変換です。`--mode auto`はローカルのC++コンパイラによる構文チェックが成功した場合だけ無変換にし、それ以外をKumaとして変換します。構文チェックには5秒の上限があり、コンパイラが使えない場合や時間切れの場合は終了します。コンパイラは`CXX`で指定できます。構文チェックではソース中のinclude先を読みます。

`--compile-commands PATH`で構文チェック用の設定を明示できます。指定がない場合でも`KUMA_COMPILE_COMMANDS`環境変数があれば使用します。通常の変換にコンパイルデータベースは不要です。

## 生成C++をコンパイルする

変換結果は`kuma.hpp`を参照します。このヘッダは`ac.hpp`と`ac_io.hpp`に依存します。変換器の配布物にこれらは含めていません。

公開ヘッダは[atcoder-headers](https://github.com/facedolid/atcoder-headers)で管理されています。互換性のある同一版の`kuma.hpp`、`ac.hpp`、`ac_io.hpp`を別の`headers/`フォルダへ置きます。入力ソースが別のライブラリをincludeしていれば、その依存も必要です。ヘッダの取得や更新を変換器が自動で行うことはありません。

GNU C++23対応のGCCを使う場合の例です。`g++`は実際にインストールしたGCCの名前に読み替えます。

```sh
g++ -std=c++23 -O2 -DAC_NO_ACL -Iheaders example.cpp -o example
printf '4\n' | ./example
```

この例の出力は`5`です。`AC_NO_ACL`はAtCoder Libraryを使わない例向けの指定です。ACLを使うソースでは指定を外し、ACLも用意します。macOSの標準`g++`はApple Clangであるため、GNU GCCとは区別してください。

## 元のソースと出力

Kumaを変換した場合は、元のソース全文とSHA-256を生成C++の先頭コメントに残します。ファイル名は末尾の名前だけを記録し、変換器から絶対パスや`#line`を追加しません。元のソース自体にパスや秘密情報があれば、コメントにも残るため、共有前に入力内容を確認してください。

無変換のC++にはコメントを付け足しません。`__LINE__`などの意味を変えないためです。使った機能に必要な実行時処理が出力に含まれるので、ソースと同じ長さになるとは限りません。名前を難読化する処理は追加していません。

## 対応範囲

try/catchと初回代入による自動宣言に対応しています。C++混在コードでの初回代入はC++コンパイラによる名前確認が必要で、最大15秒で終了します。ヘッダ不足や判定が難しい場合には明示宣言`:=`を使います。名前確認用ヘッダはこのフォルダの`include/`へ置くか、`--compile-commands`で指定します。独立版の入口とコンパイラ検出用の依存配置は、開発用CLIから切り離しています。
